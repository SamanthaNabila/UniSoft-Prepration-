# UniDesk — public demo deployment

Goal: one public URL where anyone can open and use the whole app (React + FastAPI
+ Postgres), as a throwaway demo — not permanent production.

## How it works

A single Docker image runs the FastAPI backend, which **also serves the compiled
React app** from the same origin:

| Path | Served by |
|------|-----------|
| `/api/v1/*`, `/health`, `/docs` | FastAPI |
| everything else (`/`, `/dashboard`, `/tickets/5`, assets) | the bundled React SPA (`backend/static/`) |

Because the SPA and API share one origin there is **no CORS setup and no second
URL**. A Render Blueprint provisions the web service and a free managed Postgres
and wires them together.

## Files added for deployment

| File | Purpose |
|------|---------|
| `render.yaml` (repo root) | Render Blueprint: 1 web service (Docker) + 1 free Postgres. It is at the **repo root** because Render only reads Blueprints from there; it points back into `UniDesk/` via `rootDir`. |
| `UniDesk/Dockerfile` | Multi-stage: build the Vite frontend, then a Python 3.13 image that runs migrations, seeds demo data, and serves via uvicorn. |
| `UniDesk/.dockerignore` | Keeps `node_modules`, `venv`, `.env`, etc. out of the build context. |
| `UniDesk/backend/scripts/seed_demo.py` | Idempotent seeder — a few fictional users/tickets/comments so the demo isn't empty. |

## Minimal code changes (backward-compatible)

1. **`frontend/src/services/api.js`** — API base URL is now
   `import.meta.env.VITE_API_BASE_URL || 'http://localhost:8000/api/v1'`.
   Unset (your normal `npm run dev`, tests) = unchanged. The Docker build sets
   `VITE_API_BASE_URL=/api/v1`.
2. **`backend/app/main.py`** — if a `backend/static/` directory exists (only true
   inside the deployed image), FastAPI serves `index.html` + assets and falls
   back to `index.html` for client-side routes. When the directory is absent
   (local dev, `pytest`) the block is skipped entirely — no behaviour change.

Nothing else in the application was touched.

## Deploy steps (Render)

1. **Review & push this branch.**
   ```
   git checkout unidesk-demo-deploy
   git push -u origin unidesk-demo-deploy
   ```
   (Or merge it to `main` first — Render can deploy from any branch.)

2. **Render dashboard → New → Blueprint.** Connect the GitHub repo
   `SamanthaNabila/UniSoft-Prepration-`, pick the branch, **Apply**.
   Render reads `render.yaml`, creates `unidesk-demo-db` (free Postgres) and
   `unidesk-demo` (web service), generates `SECRET_KEY`, and injects
   `DATABASE_URL`.

3. **Wait for the first deploy.** On boot the container runs
   `alembic upgrade head` → `python scripts/seed_demo.py` → `uvicorn`.

4. **Open the web service's `https://unidesk-demo-XXXX.onrender.com` URL.**
   That is the single public link to share.

If Render cannot find the Dockerfile, set the web service's
**Dockerfile Path** to `UniDesk/Dockerfile` and **Root Directory** to `UniDesk`
in the dashboard.

### Alternative: no Blueprint / no root file

Render dashboard → **New → Web Service** → select the repo → set
**Root Directory = `UniDesk`**, **Runtime = Docker**. Add a free Postgres
separately and set env vars `DATABASE_URL` (from the DB) and `SECRET_KEY`
(`openssl rand -base64 32`). `render.yaml` is then not needed.

## Safety / data hygiene

- **No real secrets ship.** `backend/.env` (your real `SECRET_KEY`) is
  git-ignored and `.dockerignore`d. The demo `SECRET_KEY` is generated by Render
  and exists only in that service.
- **No production data.** The database starts empty; the only content is the
  fictional seed data and whatever demo visitors create. All seed identities are
  fake `@unidesk.com` names with the password `Demo1234`.
- **Not permanent.** Render's free Postgres is deleted ~30 days after creation
  and the free web service sleeps when idle — appropriate for a temporary demo.
  To wipe mid-life: Render dashboard → the database → **Reset**, then redeploy
  the web service to re-seed.
- **Known limitations (from prior testing), acceptable for a demo but do not
  put this in front of real users:** no rate limiting; `ticket.description` has
  no max length; duplicate/concurrent submits create duplicate rows; some
  oversized/deeply-nested payloads return HTTP 500. Blast radius here is one
  small container + a throwaway DB. Keep the `onrender.com` subdomain (don't
  attach a real domain).
- `/docs` (Swagger UI) is publicly reachable — usually desirable for a demo; to
  hide it, construct `FastAPI(docs_url=None, redoc_url=None, openapi_url=None)`.

## Local sanity check before deploying

```
# from UniDesk/
docker build -f Dockerfile -t unidesk-demo .
docker run --rm -p 8000:8000 \
  -e DATABASE_URL="postgresql://user:pass@host:5432/db" \
  -e SECRET_KEY="$(openssl rand -base64 32)" \
  unidesk-demo
# open http://localhost:8000
```
